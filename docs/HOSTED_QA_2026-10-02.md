## Findings

### High: assignment draft attachments disappear on final submission

Reproduction on assignment 1:

1. Upload `assignment.txt` with a written student response and save a draft.
2. Observe the saved attachment link under Submitted documents.
3. Submit the assignment without selecting the file again.
4. Both the student submission and teacher review show the text but no student
   attachment. The separate teacher instruction document remains available.

Local source inspection supports the likely cause: the submission controller
assigns permitted `documents: []` directly; the empty multiple-upload field can
replace previously attached documents. This is an inference from the local
checkout, not a server-side trace. Preserve existing attachments when no new
files are supplied, and regression-test draft-save and final-submit separately.

### Blocked: Gemini is not configured in the hosted environment

Run AI analysis shows its blocking loading dialog, then returns:
`Add GEMINI_API_KEY to your .env file before using automatic grading.`
The existing score and pending-review state survive. AI scoring, image-based
analysis, transcription, and waiting-for-confirmation publication cannot be
validated until production is configured with a working key.

### Medium: accepted AIFF audio cannot be played in this browser

A synthetic AIFF response uploads, saves across navigation, and is retained in
the attempt. The grading audio control reports Unable to play media. AIFF is
listed as accepted by the app, but native playback support is browser-dependent.
Consider normalizing uploads to a browser-playable format or offering a clear
download/fallback. This does not establish a Gemini compatibility failure.

### Medium: primary navigation disappears on mobile without a replacement

At a 390 x 844 viewport the primary navigation has `display: none`, and no menu
button replaces it. The header only exposes LMS, notifications, profile, and
sign out. The assignment page fits without horizontal overflow, but Messages
and Support have no equivalent dashboard cards. Add a keyboard-accessible
mobile menu and verify access to every role-appropriate destination. The
viewport override was reset after testing.

### Low: quiz authoring loses course-origin back navigation

From course 2, Add quiz includes `from=course`. The new quiz form, created quiz,
and subsequent editor instead show Back to quizzes and return to the separate
quiz list. Material creation preserves the course destination.

### Low: repeated quiz editor labels

After adding questions, accessible field names accumulate repetitions such as
`Question type Question type Question type`. Hidden question editors appear to
share form control IDs. Use unique IDs per question/form and associate labels
with those controls. Inputs remained usable in the tested workflow.

## Limitations and follow-up checks

- PDF download emitted a browser download event, but the browser tool took an
  unusually long time to return. End-to-end saved PDF content and performance
  are not yet verified.
- Live audio capture was not attempted. The test used synthetic uploaded speech,
  not the user's microphone. Safari recording needs a real-device check.
- Email delivery was not verified in recipient inboxes or SMTP-provider logs.
  A queued/sent application notice is not proof of mailbox delivery.
- Multi-session live inbound updates require isolated concurrent browser
  sessions; sending and subsequent unread-state checks alone do not prove them.
- No destructive deletion, existing-user password change, broad role grant,
  load test, backup restore, restart, or production deployment was performed.
- New user/administrator creation and password-reset delivery were not completed.
  User creation was inspected up to its initial-password form; credential-entry
  and privileged-account creation need a separate supervised test. No extra
  user or administrator credentials were created.
- Group-class isolation, every reschedule boundary, exhaustive tenant isolation,
  every table's second page, and full mobile/Safari/Arc coverage need additional
  tests. Only the student assignment screen received a phone-width check.
